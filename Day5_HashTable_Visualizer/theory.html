Understanding Hash Collisions 🗄️

What happens when two keys hash to the same exact index? We have to resolve the collision.

1. Linear Probing (Open Addressing)

Concept: If the calculated index is already occupied, simply step forward by exactly 1 slot until you find an empty bucket. If you reach the end of the array, you wrap around to the beginning.

Example Walkthrough:

Assume Hash Table Size = 10. Hash Function = Key % 10.

1. Insert 42. Hash(42) = 2. Bucket [2] is empty. // Result: [2] = 42

2. Insert 52. Hash(52) = 2. Bucket [2] is OCCUPIED (Collision!). Probe +1: Check Bucket [3]. It is empty. // Result: [3] = 52

3. Insert 62. Hash(62) = 2. Bucket [2] is OCCUPIED. Probe +1: Check Bucket [3] - OCCUPIED by 52. Probe +1: Check Bucket [4] - Empty. // Result: [4] = 62

Pros & Cons

Pro: Extremely cache-friendly since memory is contiguous. Easy to implement.
Con: Suffers heavily from Primary Clustering (blocks of occupied slots merge together, meaning it takes longer and longer to find empty slots).

2. Quadratic Probing (Open Addressing)

Concept: Instead of stepping by 1, we step by perfect squares: 1², 2², 3², 4², etc. This rapidly spaces out colliding keys to prevent the primary clustering issue seen in Linear Probing.

Example Walkthrough:

Assume Hash Table Size = 10. Hash Function = Key % 10.

1. Insert 42. Hash(42) = 2. Bucket [2] is empty. // Result: [2] = 42

2. Insert 52. Hash(52) = 2. Bucket [2] is OCCUPIED. Step 1² (+1): Check [2 + 1] = Bucket [3]. Empty. // Result: [3] = 52

3. Insert 62. Hash(62) = 2. Bucket [2] is OCCUPIED. Step 1² (+1): Check [2 + 1] = Bucket [3] - OCCUPIED by 52. Step 2² (+4): Check [2 + 4] = Bucket [6] - Empty. // Result: [6] = 62

Pros & Cons

Pro: Eliminates primary clustering. Spreads keys out effectively.
Con: Suffers from Secondary Clustering (keys that hash to the same initial index will follow the exact same probing sequence). Also, the math can sometimes skip empty slots entirely depending on table size.

3. Separate Chaining (Closed Addressing)

Concept: Instead of searching for a new empty bucket in the array, every bucket simply contains a Linked List. If multiple keys hash to the same bucket, we just append them to the linked list at that index.

Example Walkthrough:

Assume Hash Table Size = 10. Hash Function = Key % 10.

1. Insert 42. Hash(42) = 2. Bucket [2] list is empty. Add as first node. // Result: [2] -> [42]

2. Insert 52. Hash(52) = 2. Bucket [2] list has [42]. Append to list. // Result: [2] -> [42] -> [52]

3. Insert 62. Hash(62) = 2. Bucket [2] list has [42] -> [52]. Append to list. // Result: [2] -> [42] -> [52] -> [62]

Pros & Cons

Pro: Never "fills up" (no table resizing strictly required to resolve collisions). Deletion is incredibly easy (just delete a node from the linked list).
Con: Not cache-friendly because Linked List nodes are scattered across memory using pointers. Requires extra memory for pointers.

Summary Comparison

Strategy Type Clustering Issue Cache Performance Memory Overhead
Linear Probing Open Addressing Primary Clustering Excellent None
Quadratic Probing Open Addressing Secondary Clustering Good None
Separate Chaining Closed Addressing No Clustering Poor High (Pointers)
