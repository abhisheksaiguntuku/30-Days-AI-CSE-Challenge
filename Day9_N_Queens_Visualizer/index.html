The Problem

The N-Queens problem is a classic combinatorial challenge: place N chess queens on an N×N chessboard so that no two queens threaten each other. This means no two queens can share the same row, column, or diagonal.

Algorithm: Recursive Backtracking

We solve this using backtracking. We place queens column by column. If placing a queen in a specific row of the current column doesn't lead to a threat, we recurse to the next column. If a threat is detected or we reach a dead-end, we backtrack (remove the queen and try the next row).


function solveNQueens(board, col) {
  if (col >= N) return true; // Solved!

  for (let row = 0; row < N; row++) {
    if (isSafe(board, row, col)) {
      board[row][col] = 1; // Place Queen

      if (solveNQueens(board, col + 1))
        return true;

      board[row][col] = 0; // Backtrack
    }
  }
  return false;
}

Complexity Analysis

Time: $O(N!)$

While a naive brute force is $O(N^N)$, backtracking drastically prunes the search space, reducing it closer to $O(N!)$ on average, though worst-case bounds remain exponential.

Space: $O(N)$

Memory required for the board representation and the call stack during deep recursion scales linearly with $N$.

Real-World Applications

  • Constraint Satisfaction Problems: Foundation for scheduling, resource allocation, and routing.
  • VLSI Design: Wire routing in integrated circuits where paths cannot overlap.
  • AI & Game Theory: State-space search optimization algorithms.

Pros & Cons

  • Guarantees finding a solution if one exists.
  • Highly memory efficient ($O(N)$ space).
  • Computationally expensive for large $N$ (e.g., $N > 15$).
  • Execution time varies wildly depending on the branch chosen.
